# Experience Types

Every intake experience falls into one of three types. Tag decisions with
the relevant type(s) below (`SPA`, `Modular`, and/or `Hybrid`) so they can
be filtered by experience type from the Storybook sidebar.

## Locked decision: always distinguish SPA from Modular

Going forward, a decision may not state a single rule and leave experience
type as an afterthought. Every decision must say explicitly how it applies
to SPA, to Modular, and to the Modular → SPA hybrid — including saying "the
same on all three" when that's genuinely true. A rule written as if
experience type doesn't matter is treated as incomplete, not as a
universal rule.

## SPA

A standalone intake experience that loads on its own dedicated page. The team
controls the full layout environment.

**Reality check:** There are 1-2 RamseyTrusted verticals that are doing this
already.

<Canvas of={ExperienceTypesStories.SpaExample} />

## Modular

A componentized intake that can be embedded inline on any page within the
Ramsey ecosystem. The surrounding page context is variable and outside the
team's control.

**Reality check:** These still exist across RamseyTrusted.

<Canvas of={ExperienceTypesStories.ModularExample} />

## Modular → SPA (hybrid)

A Modular experience that starts embedded on a host page, then hands off
to a dedicated SPA later in the same flow — most commonly at results. The
handoff point itself is where hybrid-specific decisions live; screens
before the handoff still follow Modular rules, and screens after it still
follow SPA rules.

**Reality check:** This is already how results work today — every
Modular intake ends by opening results in a SPA. See
[Decisions/Results and Post Funnel](?path=/docs/decisions-results-and-post-funnel--docs).
The same handoff now also applies mid-flow: any Modular intake/referral
experience with more than one step launches into a SPA rather than
running to completion inline. See
[Decisions/Modular Handoff](?path=/docs/decisions-modular-handoff--docs).
